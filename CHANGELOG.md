# Журнал изменений

## v1.3 — 2026-10-28 — заявка не остаётся без картинки

- **Ссылки на файлы в тексте.** Загрузка файла в чат требует права «Чаты»
  (`im`) у вебхука, а его включает только администратор портала. Чтобы
  заявка не ждала этого момента, в сообщении печатаются прямые ссылки на
  каждый файл GLPI: у исполнителя вход в GLPI есть, картинка открывается
  одним тапом.
- **Имена картинок.** GLPI подписывает вставленные в описание картинки
  UUID'ом `a02c31ec-…-6ae1ae8e458b45.72864680`; в чате он называется
  `картинка #1441`.

## v1.2 — 2026-10-28 — файлы в чат по-настоящему

- **Картинки из описания.** Заявка «с картинкой» в GLPI часто не имеет
  вложений вовсе: изображение ВСТАВЛЕНО в текст, и выглядит как `<img
  src="...document.send.php?docid=1441&#61;itemtype&#61;Ticket...">` со
  ЗАКОДИРОВАННЫМИ `&`/`=`. Старый разбор их не видел, поэтому сообщение
  уходило без картинки. Теперь карточка раскрывается через `html.unescape`,
  и документы собираются обоими видами: `<a>` из секции «Файлы» и `<img>` из
  описания (проверено на #2854 — две картинки нашлись и скачались).
- **Файл в чат — только `im.v2.File.upload`.** Multipart-часть `files[0]`
  коробка принимает и возвращает успех, но в чат кладёт ПУСТОЕ сообщение:
  незнакомые поля REST-слой молча выбрасывает. Документированный способ —
  base64 в `fields.content` + `fields.name` (+ `fields.message`), лимит 100 МБ.
- **Важно про автора.** Метод работает под владельцем вебхука (scope `im`),
  поэтому файл в чате появляется ОТ ИМЕНИ ПОЛЬЗОВАТЕЛЯ, а не бота — иначе
  коробка не умеет ни в групповом чате, ни в диалоге.
- **Выбор файлов.** Вместо галочки «вложения в чат» — чекбокс на каждый файл
  (🖼 картинки, 📎 документы). Нужно, чтобы не утаскивать в чат логотип из
  подписи, который GLPI притаскивает к каждому письму.
- **Частичный успех.** Если карточка ушла, а файлы нет — окно честно говорит
  «карточка ушла, файлы — нет» и показывает причину, а не «не отправлено».
- **Настройка.** Вебхуку нужно право «Чаты» (`im`): без него портал отвечает
  `insufficient_scope`, и программа теперь об этом говорит прямым текстом.

## v1.1 — 2026-10-28 — вложения и удаление заявки

- **Вложения.** Если к заявке что-то прикремлено, окно показывает «3 шт.,
  картинок 1 …», список файлов попадает в текст сообщения, а после текста в
  чат уходят сами файлы — каждый отдельным сообщением (`bitrix.send_file`).
  Файлы в GLPI закрыты входом, поэтому сначала выгружаются сессией клиента
  (`document.send.php?docid=..&tickets_id=..`), потом отдаются боту.
- **Удаление.** Кнопка «Удалить заявку» с подтверждением: `POST
  ticket.form.php` с `delete` (без права PURGE GLPI делает мягкое удаление),
  после успеха заявка убирается из окна и из состояния монитора.
- Проверено живьём: `tests\live\test_send_attachments.py`,
  `tests\live\test_delete_ticket.py` (удаление — на своей тестовой заявке,
  затем на #2851).

## v1.0 — 2026-10-28 — мост GLPI → Битрикс24 работает

Собрано: `dist\BotNotifyDesktop.exe` (один файл, рядом нужен `.env`).

### Что умеет

1. **Новые заявки.** Оператор видит заявку в окне «Заявки GLPI», выбирает
   исполнителя из всего списка GLPI и жмёт «Отправить в чат»: сообщение уходит
   в Битрикс24, а исполнитель сохраняется в GLPI.
2. **Актуализация.** Кнопка «Актуализировать сейчас» прогоняет активные
   заявки наших сотрудников **по одной**, с паузой `GLPI_REFRESH_PACE` секунд
   между сообщениями. Повторное нажатие предлагает остановить.

Ничего само в чат не пишется: ни таймеров, ни автоотправки новых заявок —
только две кнопки.

### Починено в этом заходе

| Симптом | Настоящая причина |
|---|---|
| «Назначенный не добавляется» | GLPI 11 принимает актёров полем `_actors` (JSON), а не `_users_id_assign[...]`: старые поля только добавляют, удалить никого не могут |
| «Не применилось», хотя применилось | клиент перечитывал заявку из `_tabs_cache` (30 с) — то есть видел состояние ДО правки |
| «Назначенные сейчас» ничего не делали | кнопка была проткнута к `_load_current` (обновить список), а не к записи в GLPI |
| «Отправить в чат» ничего не делала | исключение в `_drain()` рвало цикл `after(250)` — очередь вставала навсегда, `_busy` не сбрасывался |
| «Сначала выбери заявку» на открытой заявке | `list_var.set()` пересобирает `Listbox` и снимает выделение, а выбор читался из `curselection()` |
| «Открыть в браузере» вешало окно | `webbrowser.open()` на Windows запускает браузер и ждёт его — из главного потока Tkinter |
| Требовало выбирать исполнителя заново | в поле лежала строка «Иванов · Первая линия», не совпадающая ни с одним пунктом |

### Ключевые решения (подробности — `docs/glpi-bridge.md`)

- REST к GLPI нет (Legacy отключён, HLAPI требует OAuth) — работает HTML-сессия:
  вход, `common.tabs.php` на карточку, `actors.php` на кандидатов.
- `glpilist_limit=60` — список заявок одним запросом за ~0.7 с; детали заявки
  докачиваются лениво, только на выбранную.
- Актёры пишутся одним полем `_actors`, семантика — замена списка целиком.
- Диалог Битрикс24: личный — `81`, групповой — `chat7018` (префикс `chat`
  обязателен, иначе «Указанный чат не существует»).
- Ссылки открывает `web_open.open_url()` → `os.startfile`, не `webbrowser`.

### Известные ограничения

- `@упоминание` через `[USER=81]@Имя[/USER]` на этой коробке выводится
  текстом, без кликабельного выделения.
- Поток писем (IMAP → VK) живёт по-прежнему и шлёт сам — решение о нём не
  принято.
- `.env` с секретами выведен из-под git (`git rm --cached`), шаблон —
  `.env.example`.

### Проверка

Живые проверки — `tests/live/` (пишут в GLPI и чат по-настоящему, потом чинят
обратно). Сборка: `venv\Scripts\python.exe -m PyInstaller --noconfirm
BotNotifyDesktop.spec`, затем скопировать `.env` в `dist\`.
