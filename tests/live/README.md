# Живые проверки (GLPI + Bitrix24 по-настоящему)

Это **не** юнит-тесты: они ходят в рабочий GLPI и реально пишут в Bitrix24.
Запускать из корня репозитория, с заполненным `.env`:

```bat
venv\Scripts\python.exe tests\live\test_assignee_picker.py
```

Перед запуском убедись, что `BITRIX_DIALOG_ID` указывает на **личный** диалог
(`81` — сам с ботом), а не на общий чат: иначе команда уйдёт людям.

| Скрипт | Что проверяет | Пишет |
|---|---|---|
| `test_assignee_picker.py` | в выпадашке все исполнители GLPI, в поле — один | нет |
| `test_glpi_write_actor.py` | запись исполнителя в GLPI полем `_actors` (добавить + **удалить**) | да, чинит обратно |
| `test_send_to_chat.py` | кнопка «Отправить в чат» | сообщение в чат |
| `test_reassign_via_gui.py` | сменить человека в GUI → заявка в GLPI поменялась | да, чинит обратно |
| `test_assign_then_chat.py` | «Назначить в GLPI», сразу за ней «Отправить в чат» | да, чинит обратно |
| `test_selection_survives_refresh.py` | карточка не теряется после пересборки списка и прихода новой заявки | да, чинит обратно |
| `test_pick_survives_detail.py` | выбор оператора не слетает, когда асинхронно догрузились детали | нет |
| `test_open_link.py` | «Открыть в браузере» возвращается сразу, а не вешает окно | нет |
| `test_send_attachments.py 2090` | в чат уходят текст + каждый файл заявки | сообщения в чат |
| `test_delete_ticket.py 2851` | отказ ничего не меняет, подтверждение удаляет заявку | УДАЛЯЕТ заявку (нужен номер, который не жалко) |

Номера заявок в скриптах — тестовые из нашего GLPI (`2842`, `2090`); если их
удалили или закрыли, поменяй id в начале файла. Каждый скрипт, который менял
исполнителя, возвращает его обратно в последней строке — не удаляй её.
